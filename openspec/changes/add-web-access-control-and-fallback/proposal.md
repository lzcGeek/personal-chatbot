## Why

当前聊天会把用户已启用的所有 MCP 工具直接暴露给模型，用户无法在单次提问时明确禁止外部网络访问；同时，LLM、联网工具或上下文服务异常时，系统只返回原始错误或中断流，缺少一致、可理解、可恢复的降级体验。

## What Changes

- 在消息输入区增加“联网”开关，并把选择作为每次聊天请求的一部分传给后端；默认关闭，前端可记住用户最近一次选择。
- 为 MCP 服务增加“需要联网”分类，后端根据请求策略过滤工具并在执行入口二次校验，确保关闭联网时不能仅靠伪造工具调用绕过限制。
- 联网开启但没有可用网络工具时，继续使用本地会话、长期记忆和个人知识库回答，并明确提示未进行联网检索。
- 建立统一异常分类与兜底策略：瞬时 LLM 故障有限重试、联网工具失败回退本地回答、上下文检索失败隔离、工具循环超限转无工具收尾、流中断保留部分内容。
- SSE 返回稳定的错误码、用户可读信息、是否可重试及降级信息；前端展示降级状态并为可恢复失败提供“重试”操作。
- 记录结构化日志与关键指标，但不记录密钥、Cookie、MCP Header、完整用户消息或工具敏感参数。

## Capabilities

### New Capabilities

- `web-access-control`: 定义单次聊天的联网许可、网络工具分类、服务端强制过滤与前端开关行为。
- `chat-fallback`: 定义 LLM、网络工具、上下文检索和 SSE 异常时的重试、降级、持久化与用户反馈。

### Modified Capabilities

- `chat-core`: 扩展聊天请求和 SSE 事件契约，并增加失败后的重试交互。
- `mcp-integration`: 为 MCP 服务和工具增加联网属性，并限制网络工具只在获得本次请求许可时可见、可调用。

## Impact

- 后端：`ChatRequest`、聊天 API/服务、上下文构建、LLM 客户端、MCP 模型/Schema/管理器、配置及数据库迁移。
- 前端：聊天输入组件、Pinia store、聊天 API/types、消息和错误状态展示、MCP 服务配置表单。
- API：`POST /api/chat/send` 与 `POST /api/chat/stream` 新增向后兼容的 `allow_network`；SSE `error` 事件由自由文本扩展为结构化字段。
- 数据：`mcp_servers` 新增联网分类字段；现有 HTTP/SSE 服务迁移为需要联网，现有 stdio 服务保持不需要联网并可由用户调整。
- 依赖：第一阶段复用现有 MCP 工具体系，不内置或绑定特定搜索供应商，不新增第三方运行时依赖。
