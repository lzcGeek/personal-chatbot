## Context

NewAgent 当前使用 Vue 3、FastAPI、PostgreSQL、Qdrant 和 Neo4j。`ChatService` 负责持久化、上下文构建、单一 LLM 工具循环和异步事实抽取；`ContextBuilder` 组合固定系统提示词、最近消息、会话语义记忆、文档证据与 MCP 工具。文档上传总是进入文本索引，并在 Neo4j 可用时进入图谱抽取。会话和消息尚未表达说话角色、群组成员、摘要、附件或媒体任务。

本变更跨越数据模型、聊天执行、异步任务和前端交互，必须保持现有 API 和纯文本助手模式可用。所有数据继续按 `user_id` 隔离；上传文档、角色描述和外部媒体结果均视为不可信内容。

## Goals / Non-Goals

**Goals:**

- 在现有会话旁增加可选的单 NPC 和多 NPC 模式，不改变普通助手会话的默认行为。
- 提供稳定、可测试的角色 Prompt 分层和群聊发言路由。
- 在上下文超限前异步生成可追溯摘要，并将记忆限定到角色或共享场景作用域。
- 允许用户按文档选择是否构建图谱，按会话选择检索模式。
- 通过统一 Provider 接口接入图片生成和 TTS，并在未配置或失败时安全降级。
- 为后续 Character Card、世界书和更多本地/云媒体 Provider 留出扩展点。

**Non-Goals:**

- 首版不实现完全自治的后台 Agent 团队、任意工作流图或角色之间无限自循环。
- 首版不保证完整兼容 SillyTavern Character Card 的全部版本和扩展字段。
- 不在首版提供视频生成、实时语音通话、Live2D、VRM 或声音克隆训练。
- 不允许角色 Prompt、文档或模型输出直接扩大 MCP、联网和 Provider 权限。
- 不要求部署者同时配置 Neo4j、图片和 TTS 服务。

## Decisions

### 1. 普通助手模式作为显式兼容路径

`conversations` 增加 `mode`、`routing_strategy`、`retrieval_mode` 和运行时配置，默认分别为 `assistant`、`manual`、`auto`。普通助手模式继续执行现有单响应链路，不创建隐式角色，也不改变旧请求体。

相比把原助手迁移成系统角色，这可避免历史消息、引用和客户端被迫迁移；代价是聊天服务暂时保留兼容分支。

### 2. 角色定义与会话成员分离

新增用户私有 `characters`，保存稳定人设和默认能力；新增 `conversation_members`，保存会话内顺序、启用状态、角色备注和覆盖配置。删除角色时，有历史消息引用的角色采用软删除，消息保留显示快照。

消息保存 `character_id` 和 `speaker_name` 快照。这样角色改名或删除不会改写历史，同时同一角色可加入多个不同场景。

### 3. Prompt 使用固定优先级分层

上下文顺序为：平台安全约束 → 工具/联网授权 → 会话场景与世界状态 → 当前角色人设 → 角色记忆与共享记忆 → 文档证据 → 历史摘要 → 最近原始消息。用户填写的人设、示例对话和知识材料使用清晰边界标记，不能覆盖平台权限。

不允许角色保存任意裸 `system` 消息数组，以降低 Prompt 注入和不同模型格式差异。

### 4. 编排器只选择发言者，生成仍复用单角色执行器

新增 `NpcOrchestrator`，输入成员、用户消息和策略，输出有序 `speaker_plan`。支持 `manual`、`mention`、`round_robin` 和 `auto`；`auto` 使用受限结构化输出，只能从当前启用成员 ID 中选择。每轮设置最大角色数和最大连续生成数，默认一个角色。

每个选中角色依次调用同一个角色执行器，上一角色的已落库回复可成为下一角色上下文。首版不并行生成，以避免角色看不到同轮前文、流式事件难排序及费用失控。

### 5. 分层记忆使用 PostgreSQL 事实源和 Qdrant 可重建索引

保留当前 `memory_entries` 与 outbox 模式，增加 `scope`、`character_id`、`importance`、`validity` 和替代关系。新增 `conversation_summaries` 保存覆盖的消息边界、摘要文本、版本和生成状态；新增 `conversation_state` 保存经过 schema 校验的共享场景状态。

压缩由异步任务在消息数或估算 token 达到阈值时触发。只有已完成且覆盖连续消息区间的摘要才能进入上下文；摘要失败时继续使用最近原文并记录降级，不删除原始消息。

记忆冲突采用混合策略。用户明确表达“不是、改成、现在、不再”等纠正时，新事实自动替代同作用域的旧事实；地点、关系、任务和物品等状态变化保留时间版本并将旧版本标为历史；仅由模型推断出的疑似冲突进入 `pending_confirmation`，在确认前不替代当前有效事实；能够同时成立的偏好和属性并存。原始消息始终不可改写，所有替代关系保留来源消息和原因。

### 6. 图谱建立与图谱检索分别控制

文档增加 `graph_mode = inherit|enabled|disabled`。上传始终完成解析和向量索引；仅有效模式为 enabled 且 Neo4j 可用时排队图谱任务。已跳过的文档可通过显式 API 补建或重建图谱。

会话 `retrieval_mode = auto|off|vector|hybrid`。`auto` 保持当前行为；`vector` 禁止图查询；`hybrid` 在图服务失败时返回向量结果并报告降级。该设计与文档任务解耦变更兼容，不让图谱阻塞文本可检索状态。

### 7. 媒体采用能力注册表和异步附件任务

定义 `ImageProvider` 与 `TtsProvider` 接口和 Provider 注册表。首批实现以 OpenAI 兼容 HTTP 接口为基线；本地 ComfyUI、GPT-SoVITS/CosyVoice 等作为后续适配器。角色只引用逻辑 Provider 配置和 voice/image profile，不接触明文密钥。

文本消息先完成并持久化，再按用户动作或角色自动策略创建媒体任务。任务结果写入 `message_attachments`；SSE 发送媒体任务状态事件。TTS 或图片失败不改变文本消息状态。

### 8. Provider 密钥先采用管理员环境配置

首版使用部署者环境变量和服务端 Provider 注册表，不开放用户提交任意 endpoint 或密钥。这样可先建立调用边界、超时、媒体大小和成本限制。用户自带密钥作为后续能力，届时需引入独立加密密钥、密钥轮换和 SSRF 防护。

### 9. 分阶段迁移和功能开关

数据库先增加可空字段和新表，再部署兼容读写代码，最后开放前端入口。角色、群组、压缩、图片和 TTS 分别受服务端能力开关控制。旧会话保持 `assistant` 模式，旧消息 `character_id` 为空。

## Risks / Trade-offs

- [自动路由模型选错角色或产生额外费用] → 约束候选 ID、默认单角色、提供手动/提及模式并记录路由原因。
- [多个 NPC 造成上下文和费用倍增] → 限制单轮发言者、连续轮数、字符/token 预算和媒体自动生成次数。
- [摘要遗漏关键剧情或改变事实] → 保留原始消息、记录覆盖范围、允许查看/重建摘要，重要状态使用结构化记忆而非只依赖摘要。
- [角色 Prompt 或文档诱导调用工具] → 权限由服务端交集计算，角色内容置于不可信边界内，执行入口再次校验。
- [图谱关闭后用户误认为知识库不可用] → 前端分别展示“文本可检索”和“图谱增强”状态，并明确向量检索仍可用。
- [媒体服务带来 SSRF、超大文件或敏感数据泄露] → 首版仅管理员允许列表、固定 endpoint、响应大小/MIME 校验、超时和私有附件授权。
- [大范围一次上线难以回滚] → 以兼容迁移和独立开关分阶段交付，每阶段均可关闭而不删除用户数据。

## Migration Plan

1. 先完成现有文档文本索引与图谱任务解耦，确保图谱失败不影响文本就绪。
2. 新增兼容数据库迁移：角色、成员、会话模式、消息说话者、记忆作用域、摘要、状态、媒体任务和附件。
3. 上线角色 CRUD、普通/单 NPC 会话和角色化 Prompt，保持所有旧会话为普通助手。
4. 上线文档图谱构建选择和会话检索模式，并为已有文档设置 `inherit`。
5. 上线摘要任务和分层记忆，先仅观测生成结果，再开启上下文替换。
6. 上线手动、提及和轮询编排；验证限额后再启用自动路由。
7. 上线管理员 Provider、手动图片/TTS，再选择性开放角色自动媒体策略。
8. 回滚时关闭功能开关并回退应用版本；新增表和可空字段暂时保留，Qdrant/Neo4j/媒体派生数据均可重建或延后清理。

## Open Questions

- 自动路由首版是否需要旁白/GM 特殊角色，还是将 GM 视为普通成员加标签。
- 首个生产图片 Provider 与中文 TTS Provider 的优先级，以及部署环境是否允许本地 GPU 服务。
- 后续是否允许用户自带 API 密钥；若允许，需要确定主密钥托管和计费/额度策略。
- 是否在首版支持 Character Card V2 导入导出，或在角色核心稳定后另立变更。
